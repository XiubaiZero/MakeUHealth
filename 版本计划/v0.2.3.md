## 2. 语义意图识别

### 分类与路由

识别五类：`HEALTH`、`CAPABILITY`、`OUT_OF_SCOPE`、`CLARIFY`、`SOCIAL`。

- 明确健康任务进入现有问答及记忆链路；即使混有问候、能力询问，也优先处理健康任务。
- 功能介绍、范围外、真正无法确定意图、单纯问候分别返回中英文固定回复。
- 健康问题缺少详细资料时，仍进入问答链路，由模型询问资料。
- 追问结合会话上下文；明确切换主题时，以当前问题为准。

分类接收当前问题、语言、记忆开关允许的最近 **3 个完整问答轮次**及已有摘要；不额外生成摘要。完整健康档案和长期记忆继续用于主问答。

| 分类参数   | 初始值                        |
| ---------- | ----------------------------- |
| 模型与鉴权 | 复用现有后端配置              |
| 思考模式   | 关闭                          |
| 温度       | `0`                           |
| 输出上限   | `256 token`                   |
| 超时       | `10 秒`                       |
| 输入预算   | `8,192` 个 UTF-8 字节保守单位 |
| 自动重试   | 不重试                        |

| 数       | 新分类步骤        | 原有链路                                     | 设置用意                                                   |
| -------- | ----------------- | -------------------------------------------- | ---------------------------------------------------------- |
| 温度     | `0`               | 问答仍为 `0.4`；摘要、提取仍为 `0`           | 分类更重视稳定选择类别，减少措辞变化；不保证结果完全一致   |
| 输出上限 | `256 token`       | 问答仍为 `4096`；摘要、提取仍为 `2048`       | 分类只返回简短 JSON，预留格式余量，不需要长篇回答          |
| 调用超时 | `10 秒`           | 主问答上限仍为 `60 秒`；辅助调用仍为 `20 秒` | 限制新增步骤的等待时间，超时后继续主问答                   |
| 输入预算 | `8192` 个保守单位 | 主链路仍为 `32768`                           | 限制分类成本；这里按 UTF-8 字节估算，**不是实际 token 数** |
| 近期历史 | 最近 `3` 轮       | 主问答仍为最近 `12` 轮                       | 帮助识别追问，同时控制分类输入长度                         |
| 思考模式 | 关闭              | 延用现有设置                                 | 分类任务较简单，先采用较轻的调用方式                       |

使用独立、带版本标识 `intent-v1` 的提示词和 JSON 模式，仅接受 `{"intent":"HEALTH"}` 形式的合法类别。输入超预算时，依次移除最旧完整轮次、摘要；仍超预算则降级到主问答，不截断当前问题。

### 兼容与失败处理

- 每轮只分类一次，协调入口传递分类结果；移除 API 路径中的重复判断和前端关键词提前拦截。
- 分类失败直接进入现有受健康范围提示词约束的问答链路，不再由旧关键词规则拒绝。
- 本地模式、缺少密钥及规则模式继续沿用原实现。
- 新参数独立配置，不覆盖原有问答温度 `0.4`、输出 `4096`、最近历史 `12` 轮，以及摘要／提取输出 `2048` 等设置。
- 保留前端请求超时 `60 秒`、异步任务过期 `180 秒`；旧同步入口新增整轮 `55 秒` 期限，各步骤按剩余时间调用。
- 模型调用在数据库事务外进行，保留单会话单轮生成、请求去重和迟到结果检查。
- 使用现有消息元数据保存可选分类信息，不新增意图表；旧接口正文、错误结构及记忆计数保持兼容。
- 提供 `assistant.intent.mode=rules|semantic`；开发期间使用规则模式，验收通过后发布默认语义模式。

## 3. 聊天输入与账号设置

### 快捷键和空白校验

在智能助手页面打开现有设置弹窗时，新增 **“开启回车键发送消息”**，默认开启，提供中英文文案和输入框快捷键提示。

| 设置状态 | 快捷键行为                                        |
| -------- | ------------------------------------------------- |
| 开启     | Enter 发送；Ctrl+Enter 换行；Shift+Enter 保留换行 |
| 关闭     | 恢复旧版输入行为：Enter 换行，点击按钮发送        |

Ctrl+Enter 在光标处插入换行，支持替换选中文字并保持光标位置。其他组合键不新增发送行为。

键盘发送和按钮发送共用发送入口：

- 先检查去除首尾空白后的内容；空字符串、空格、制表符、换行及全角空格组成的消息，弹出“不能发送空白消息，请输入内容。”。
- 空白校验在编辑确认之前执行；不创建会话、消息或模型任务，保留输入内容。
- 发送按钮保留生成中、离线等限制；取消单纯因输入为空而禁用，让点击发送也能触发警告。
- 中文输入法选词期间的 Enter 不发送；长按、重复按键、正在生成或弹窗打开时不重复提交。
- 编辑后重新发送仍经过现有确认流程。
- 警告弹窗支持确认、Escape 关闭及焦点返回输入框，并适配移动端。

### 跨设备保存

新增独立账号偏好表，保存 `account_id`、`enter_send_enabled`、`revision`；新账号和没有偏好记录的已有账号默认开启。初始化脚本可重复执行，不重置已保存设置。

新增登录后接口：

- `GET /api/assistant/preferences`：返回 `{enterSendEnabled, revision}`。
- `PATCH /api/assistant/preferences`：接收 `{enterSendEnabled, expectedRevision}`，返回保存后的状态。
- 账号从登录身份取得；非法参数返回 `400`，版本冲突返回 `409`，存储不可用返回 `503`。

设置独立于模型记忆；切换它不取消生成、不修改记忆版本。

前端使用共享偏好状态，进入聊天页、打开设置和页面恢复可见时刷新；聊天页可见期间每 `15 秒` 同步一次，隐藏或离开后停止。

已确认的失败行为：

- 首次加载设置失败时，**仍默认开启 Enter 发送**，显示加载失败与重试入口。
- 已读取过设置后刷新失败，保留最近确认的值。
- 保存成功后应用新值；保存失败保留原值，不积累离线修改。
- 冲突时读取最新设置并提示用户重新选择。
- 切换账号或退出登录时清理状态，丢弃旧账号的迟到响应。

### 聊天输入与账号偏好（本次追加确认）

- 智能助手页面的设置新增“开启回车键发送消息”，默认开启；Enter 发送、Ctrl+Enter 在光标处换行、Shift+Enter 换行。关闭后恢复 Enter 换行和按钮发送。
- 键盘和按钮共用发送入口，空白内容弹出“不能发送空白消息，请输入内容。”；先校验空白，再处理编辑重发确认。中文组合输入与重复按键不误发送，离线及生成中暂停发送。
- 新建独立表保存 account_id、enter_send_enabled、revision；幂等初始化不重置偏好，不影响记忆版本或生成任务。
- 登录后 GET /api/assistant/preferences 返回 {enterSendEnabled,revision}；PATCH 接收 {enterSendEnabled,expectedRevision}，账号从身份取得，非法参数 400、冲突 409、存储不可用 503。
- 进入聊天页、打开设置及恢复可见时刷新；可见期间每 15 秒同步，隐藏和离开停止。切换账号清理状态并丢弃迟到响应。
- 首次设置加载失败仍默认开启，后续失败保留最近确认设置；保存成功后应用，保存失败保留原值，冲突刷新并提示重新选择，不积累离线修改。
- 补充真实模块、独立数据库、HTTP、浏览器和移动端测试；未执行检查明确标注。

## 4. 测试与验收

### 免费验证

运行前后端测试和生产构建，使用模拟模型覆盖：

- 五类意图、中英文、模糊追问、主题切换、关键词误导、记忆关闭及分类失败降级。
- 参数隔离、分类次数、输入预算、整体超时、并发请求和原有编辑删除行为。
- Enter 发送、Ctrl+Enter 光标换行、关闭后的旧行为、中文输入法及重复按键。
- 各种空白消息弹窗、按钮校验、编辑确认、离线和生成中禁止重复发送。
- 默认开启、重新登录、两设备同步、账号隔离、保存失败及版本冲突。
- 数据库重复初始化不重置关闭偏好，清除记忆不改变输入设置。
- 移动端弹窗、开关和快捷键提示布局。

数据库检查使用独立测试库。浏览器验收不调用付费模型；未运行的检查明确标注，不记为通过。

### 真实模型评测

保持原预算：**累计最多 3 元、60 次调用，达到任一上限即停止**。

- 20 个分类案例，每类 4 个，覆盖中英文；重复两次，计划 40 次分类调用。
- 5 个核心场景进行旧、新链路对照。
- 分类、问答、摘要及改写全部计入预算；剩余额度用于必要复测，不重置账本。
- 评测前核对官方价格，请求前预留费用；缺少 usage 时保留预留额度。

报告记录预期与实际类别、回答、调用次数、usage、费用及分类和整轮耗时。发布要求：分类正确率至少 **90%**，核心误分流案例全部通过，已有记忆追问无回归，新输入功能和跨设备偏好通过验收。

预算耗尽或关键验收失败时，记录问题并暂停发布。
