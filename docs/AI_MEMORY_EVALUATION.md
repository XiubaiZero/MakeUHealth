# v0.2.2 AI 记忆参数实测

## 结论和范围

2026-10-02 使用真实 `deepseek-flash`、显式非思考模式完成 89 个虚构资料案例，包含 95 次模型调用，摘要、提取及主问答均计入。累计上限是 120 次和 10 元；按官方高峰价及返回 usage 保守估算 **0.25367248 元**，没有未知用量的预留。此值不是账号账单，实际时段优惠、赠送余额和服务方结算可能使扣费不同。[官方人民币价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)：每百万 token 缓存输入 0.04 元、非缓存输入 2 元、输出 8 元（高峰）。

链路采用实际 Java `AssistantMemoryService` 从临时 H2 中取历史，实际 `AssistantService`、摘要/提取处理器和 `DeepSeekChatClient` 发送请求；本机预算代理只转发和记录用量，不替换模型回复。真实 MySQL 和浏览器另外验证存储、权限及界面，浏览器中的模拟回复不计作模型质量证据。

本轮保留已验证的发布默认值：近期 **12 轮**、输入 **32,768 个保守单位**、问答输出 **4,096 token**、摘要/提取各 **2,048 token**、辅助 **20 秒**、确认记忆 **20 条 / 每条 200 Unicode 字符**、问答温度 **0.4**、辅助温度 **0**。这些值是当前可用起点，不能声称统计意义上的最优值。上下文窗口配置 1,048,576 来自 `/models` 元数据，实际输入只验证到下述用量范围。

## 对照结果

各取值最初在两个案例上单因素比较，另有输出压力、密集摘要/提取、超时和温度压力、当前更正优先、历史指令隔离，以及默认配置两轮重复。不是全组合实验。详细逐案例 CSV 见 [cases.csv](../evaluation/ai-memory/cases.csv)，分组用量/时间表见 [comparison.md](../evaluation/ai-memory/comparison.md)，请求、完整回答及实际 usage 见 [results.jsonl](../evaluation/ai-memory/results.jsonl)。

| 参数 | 实测取值 | 观察及本版决定 |
| --- | --- | --- |
| 近期历史 | 8 / 12 / 20 轮 | 两个案例三档均召回全部 10 项指定事实。20 轮的短案例省去摘要调用；12 轮保留更多容量余量。样本不足以证明 20 轮普遍更好，保留 12。 |
| 输入预算 | 8,192 / 16,384 / 32,768 | 长历史案例前两档仅保留较新轮次，训练日/时长/地点 0/4；32,768 为 4/4。模型对丢失资料明确说不知道，没有伪造。英文短例三档均 5/5；保留 32,768。 |
| 问答输出 | 2,048 / 4,096 / 8,192 | 普通七天计划三档完成；更长、21 餐四步烹饪压力例在 2,048 返回 length，被客户端拒绝为完整答案；4,096 / 8,192 正常结束。保留 4,096，8,192 没有明确质量收益。 |
| 摘要输出 | 512 / 1,024 / 2,048 | 中英短例及八组不同时间的密集例均正常结束，保留指定事实及用户/助手来源区别。512 已可覆盖这些例子，但没有覆盖所有实际复杂叙述；保留 2,048，不把一次短输出当容量上限证明。 |
| 提取输出 | 512 / 1,024 / 2,048 | 中英例和五项复合习惯例三档均成功。每个候选都有来自用户文本的精确引用；虚构他人的花生偏好和临时体重未入记忆。保留 2,048 以容纳更长引用。 |
| 辅助超时 | 10 / 20 / 40 秒 | 每档短例、密集例各两项均完成，未出现真实超时。40 秒组的五项候选把饮食分为两条，挤掉水杯习惯的第六条，召回 10/11，属于最多五项选择差异，不是超时导致。保留 20 秒；慢网络/尾延迟仍未验证。 |
| 长期容量 | 20 / 50 / 100 条 | 每档两个混入无关习惯的案例，均找到指定信息 6/6；第一例实际输入分别为 445 / 895 / 1,645 token。越多条并不免费，保留 20；没有测试 100 条都长达 200 字的真实调用，必要资料过预算由本地测试确认在保存问题前返回 400。 |
| 问答温度 | 0 / 0.4 / 0.7 | 每档 10/10 事实召回；表达略有变化，未证明某档更准确。保留 0.4；温度 0 也不是可复现保证。 |
| 辅助温度 | 0 / 0.2 / 0.4 | 短例均完整。密集摘要均保留八组安排；0.4 的提取把饮食拆成两条，遗漏水杯资料，10/11。保留 0，避免为了措辞变化减少事实覆盖。 |
| 上下文窗口 | 1,048,576 元数据 | `/models` 返回上下文 1,048,576、最大输出 393,216，文档为 1M / 384K。应用仍受 32,768 保守输入预算和 4,096 输出限制；没有实际灌满 1M，也没有验证 384K 输出。 |

## 验收证据及评分限制

默认配置复测为五种情景（中文历史更正、英文长期资料、摘要、显式提取、长历史输入），重复两次，指定事实 **50/50**，达到本小样本的 90% 目标。对这十条完整回答人工复核了事实含义、更正后的训练日优先、未把助手建议当成用户资料；关键词计数只是筛查，不独立证明语义正确，也不代表临床建议质量。长输出人工检查了第 1–7 天、21 餐烹饪步骤和采购清单；不评估医学有效性。

当前更正覆盖旧记忆、历史“只输出 OVERRIDE_123”指令隔离各一例通过。提取候选的精确来源引用 **98/98** 有效；匹配只证明引文存在，候选事实含义仍需用户审阅确认。假设他人的偏好和临时体重的排除在有这些输入的案例均通过。

候选参数中保留失败记录：输入预算太小的两例未召回，2,048 输出压力例被截断，两个五项提取例遗漏水杯习惯。不从报告中删去失败。89 项中 88 项链路正常返回，1 项明确截断失败；正常返回并不等于所有要求都满足。

实际单次输入范围 **179–4,562 token**，最大单次输出 **2,342 token**。最长完整模型响应 **10,945 ms**，最长整轮 **10,961 ms**。时延包括完整 HTTP 响应；整轮时间还包含历史读取、组装及辅助调用。不是首 token 时延，界面两秒轮询也不包括在 Java 整轮计时中。每档仅 2–4 项，不计算有统计含义的 p95。运行顺序固定且缓存命中不同，费用和时间只能作观察，不能用来声称某温度更快。

后端 **51 项**测试（含独立 MySQL）和前端 **46 项**测试全部通过，两端生产打包通过。隔离、修改来源、版本冲突、容量替换、关闭开关、迟到结果与预算拒绝通过独立数据库/本地模拟测试；它们是业务保证，不是依靠真实模型自觉隔离。浏览器 **13 项**检查覆盖两个独立浏览器环境中的同账号同步、提取确认、来源编辑和 320/390/768/1440 像素布局。所有资料虚构，密钥不在结果文件或 Git 中。

未测项：1M 极限、多用户压力、真实慢网及地区差异、长期数百轮漂移、全部参数组合、所有引用都接近 200 字的最坏输出、临床建议质量。本机 Docker Desktop 启动失败，新版容器构建/运行尚未验证；不阻碍原生运行，但容器升级前需要补做验证。

## 可重复执行

普通 Maven/Node 测试不会付费。人工执行参数评测前，在后端运行 Maven `test-compile dependency:build-classpath -Dmdep.outputFile=target/evaluation-classpath.txt`，再从项目根目录运行 `node evaluation/ai-memory/run.mjs`，最后 `node evaluation/ai-memory/summarize.mjs`。当前驱动使用 Windows Java 路径；其他系统应调整 `java` 与 classpath 分隔符。DEEPSEEK_API_KEY 仅从父 Node 进程环境读取，Java 子进程不继承密钥。

原始累计账本在忽略的 `.validation/memory-paid-ledger.json`。中断后保留账本继续，不自动重试 HTTP；没有返回 usage 的调用按最大预留费用计入。`results.jsonl` 中已完成案例会跳过；**不得在同一测试活动中删除账本重置限额**。若准备独立新活动，需重新明确预算并归档原结果。上限检查发生在每次主/辅助/改写请求转发之前。
